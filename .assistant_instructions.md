# AI Agent Instructions — DS-Master-Repo

This file provides context for AI assistants helping with DS projects at Etex.

---

## Context

This is the **single shared repository** for all Data Science projects at Etex. Each project is an independent Databricks Asset Bundle (DAB) in its own top-level folder, deployed by one shared CI/CD pipeline. The architecture mirrors `da-mdp-foundations-databricks` (the platform services repo).

**Key principle:** New projects are added as folders, NOT as new repos. No new pipeline setup, no new permissions.

---

## Architecture Overview

- **Platform:** Azure Databricks (3 workspaces: DEV/TEST, ACC, PRD)
- **CI/CD:** Azure DevOps Pipelines (`Etex Portfolio 2.0` project, org `etexit`)
- **Deployment:** Databricks Asset Bundles (DAB) via shared template `da-mdp-foundations-deployments`
- **Data Pattern:** Bronze → Silver → Gold medallion architecture in Unity Catalog
- **Environments:** D (dev), T (test), A (acceptance), P (production)
- **Bundle structure:** Each project has its own `databricks.yml`, `resources/`, and `src/`

Each top-level folder with a `databricks.yml` is discovered and deployed by the CI/CD pipeline.

## Medallion Architecture (Bronze → Silver → Gold)

| Layer | Schema | Purpose | Typical Operations |
|-------|--------|---------|-------------------|
| **Bronze** | `{catalog}.bronze` | Raw ingested data | Join sources, snapshot, minimal transforms |
| **Silver** | `{catalog}.silver` | Cleaned & enriched | Filter, deduplicate, enrich, type cast |
| **Gold** | `{catalog}.gold` | Business outputs | ML predictions, KPIs, aggregations |

### Table Naming Convention
```
{catalog}.{layer}.{project}_{description}
```

### Config File Helpers
The `config_file.py` in each project exposes:
```python
bronze_table("my_raw_data")   → "{catalog}.bronze.my_raw_data"
silver_table("my_clean_data") → "{catalog}.silver.my_clean_data"
gold_table("my_predictions")  → "{catalog}.gold.my_predictions"
```

## Key Files & What to Customize (Per Project)

| File | What to Change |
|------|----------------|
| `<project>/databricks.yml` | `bundle.name`, catalog prefix, permissions |
| `<project>/resources/<project>.job.yml` | Job name, notebook paths, schedule, cluster |
| `<project>/src/notebooks/config_file.py` | Catalog prefix, table names |

Files that DON'T need changes per project:
- `pipelines/Automation_Deploy_Databricks_*.yml` (shared infrastructure)
- `pipelines/variables/databricks_variables_*.yml` (shared infrastructure)

## Deployment Flow

```
feature branch → TEST (manual) → PR (feature → main) → ACC (automatic) → merge → PRD (automatic)
```

The shared deploy template iterates over all project folders and deploys each bundle to the target environment.

---

## Common Pitfalls (Warn Users About These)

1. **`databricks.yml` missing from project folder** → "No bundles to deploy"
2. **Variable template paths with double prefix** → `pipelines/pipelines/variables/...` error
3. **Notebook paths relative to wrong location** → Use `../src/notebooks/<name>.py` from `resources/`
4. **Wrong Azure DevOps project** → `Etex Portfolio 2.0` (NOT `Etex-Portfolio`)
5. **Build Service permissions not set** → "GenericContribute" error
6. **Running ACC pipeline from wrong branch** → Must use build validation via PR
7. **Forgetting to create schemas** → `config_file.py` handles this automatically

## When Helping Set Up a New Project

1. Ask the user for:
   - Project name (for bundle name and job name)
   - Catalog prefix (e.g., `automation`, `general`, `finance`)
   - What data goes in each layer (bronze sources, silver transformations, gold outputs)
   - Number of notebooks/tasks and their names
   - Schedule requirements
   - Cluster size needs
   - Team members who need CAN_MANAGE permissions

2. Then help them:
   - Copy `hello-world/` to a new project folder
   - Customize `databricks.yml` (bundle name, catalog, permissions)
   - Customize the job YAML (tasks, notebook paths, schedule, cluster)
   - Update `config_file.py` (catalog prefix)
   - Create their notebooks following `01_bronze_*`, `02_silver_*`, `03_gold_*` pattern
   - Validate locally with `databricks bundle validate --target D`
